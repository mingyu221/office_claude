## 1. 무엇을 검사했나

도킹 브리프 3절의 검산("중심이 REF 에서 1 Å 안쪽")을 321개 전량에 적용했다.

```
REF = 1SU6 chain A PHE41 CA = [48.884, -6.486, 31.065]
center_dev = |각 구조의 41등가 CA - REF|
```

조립본이 모두 1SU6 좌표계에 놓여 있으므로, 41등가 잔기는 REF 에 거의 포개져야 한다.

### 1.1 결과 — 깨끗한 단절

```
<= 1.0 A   297건
1.0~1.5     18건
1.5~2.0      2건
2.0~5.0      0건   <- 완전히 비어 있음
> 5.0        4건
```

**2.0~5.0 구간이 공백**이므로 4건은 연속 분포의 꼬리가 아니라 별개 집단이다.
임계값을 2.0 으로 잡든 5.0 으로 잡든 같은 4건이 걸린다.

## 2. `master_1827.tsv` 의 `f41_pos` 손상 (요청 1)

| 문제 | 개수 | 해당 |
|---|---|---|
| 결측 (NaN) | **23** | `A0AB*` / `A0AC*` — **ColabFold 예측 23개와 정확히 일치** |
| 값 오류 | **6** | 정렬 재계산값과 불일치 |

`f41_pos` 는 정렬에서 나오는 값이라 AFDB 등재 여부와 무관해야 하는데,
결측 집합이 ColabFold 23개와 정확히 겹친다. master 병합 과정에서 누락된 것으로 보인다.

**`chcodh2_alignment.tsv` 로 재계산하면 321개 전부 복구된다** (결측 0 확인).

```python
def equiv41(r):                      # ChCODH2 41번의 등가 위치
    qi, ti = int(r.qstart)-1, int(r.tstart)-1
    for qc, tc in zip(r.qaln, r.taln):
        if qc != "-": qi += 1
        if tc != "-": ti += 1
        if qc != "-" and tc != "-" and qi == 41: return ti
    return None
```

재계산값으로 검사했을 때 **317/321 에서 "정렬 재계산값 == REF 최근접 CA"** 로 일치했다.
즉 재계산 자체는 신뢰할 수 있고, master 쪽만 고치면 된다.

## 3. 정렬 정합 검사 — Gly-x-Gly 모티프

ChCODH2 의 결합부위는 **G40 - F41 - G42** 다.
상동체에서도 이 모티프가 보존되는지 보면 정렬이 제대로 정합됐는지 알 수 있다.

### 3.1 정상 대조 2건

| accession | 40등가 | 41등가 | 42등가 | center_dev |
|---|---|---|---|---|
| A0A6I3SJ71 | **GLY**37 | **PHE**38 | **GLY**39 | 0.04 |
| A0A1H6XVY3 | **GLY**37 | **PHE**38 | **GLY**39 | 0.08 |

Gly-Phe-Gly 가 정확히 보존되고 41등가 CA 가 REF 에 사실상 포개진다.

### 3.2 문제 4건 — 전부 정합 실패

| accession | 40등가 | 41등가 | 42등가 | 실제 모티프 | dev |
|---|---|---|---|---|---|
| A0A2N7PLW0 | GLU129 | PHE130 | GLU131 | Glu-Phe-Glu | 5.25 |
| A0AC61KYD2 | LYS39 | ASP40 | ALA41 | Lys-Asp-Ala | 9.55 |
| A0A484HNT9 | GLU98 | PHE99 | **GLY106** | Glu-Phe-…Gly | 8.01 |
| A0AC61SBG3 | GLU39 | GLU40 | ALA41 | Glu-Glu-Ala | 8.68 |

**넷 다 Gly-x-Gly 가 아니다.**
A0A484HNT9 은 41→99 인데 42→106 으로 **7잔기 점프** — 정렬 갭이 하필 결정적 위치에 걸쳐 있다.

> **주의 — 검사 코드의 함정**
> 잔기명을 `resname[0]` 으로 판정하면 **GLU 와 GLY 가 둘 다 'G'** 라 Glu 가 Gly 로 통과한다.
> 실제로 이 실수로 한 번 잘못 판정했다. 반드시 3문자 전체로 비교할 것.

## 4. 4건 개별 진단

### 4.1 A0AC61SBG3 — **재조립 요청 (요청 2)**

REF 최근접 CA 6개에 **B 사슬 잔기가 포함**된다.

```
A/ASP57(1.8)  A/GLN44(4.7)  A/VAL58(4.9)  A/VAL56(5.2)  A/SER38(5.5)  B/ARG60(5.6)
                                                                      ^^^^^^^^^^^^
```

정상 2건과 다른 제외 3건은 최근접 6개가 **전부 A 사슬**이다.
이 구조만 반대편 protomer 가 결합부위까지 밀고 들어왔다.
육안 검토에서도 "이량체 반대편 모델 배치가 1SU6 과 많이 다르다"로 확인됨.

**유력한 원인 — 참조 이량체 오선택.**
`structure_pipeline` 셀 10 에 이런 처리가 있다.

```python
n_fill = int(sel2.arch.isna().sum())
if n_fill: print(f"※ arch 없음 {n_fill}개 → SF4 기본값...")
```

`arch` 가 결측이면 **SF4 로 기본값 처리되어 1SU6 에 붙는다.**
실제 아키텍처가 SF2 라면 6OND 를 써야 하고, 그렇지 않으면 **반대편 사슬만 틀어진다** —
관찰된 증상과 정확히 일치한다.
이 구조는 `f41_pos` 결측 23개 중 하나이기도 해서 메타데이터가 부실할 가능성이 높다.

**확인·수정 방법**: 참조(1SU6 · 6OND) × 모드(global · local) 네 조합을 전수 비교하고
`center_dev` 가 가장 작은 것을 채택. 아래 6절 통과 기준 참조.

**같은 문제가 다른 구조에도 있을 수 있다.** `arch` 결측인 구조 전체를 한 번 훑어볼 것.

### 4.2 A0A484HNT9 — 중심 후보 확정됨

REF 8 Å 이내 후보 중:

```
HIS104   3.10 A   이웃 GLY-HIS-GLY   <- Gly-x-Gly 완전 일치
LEU110   5.53 A   이웃 GLY-LEU-CYS
```

**`HIS104` 가 진짜 41등가로 보인다.** 정렬의 PHE99(8.0 Å)는 갭 때문에 밀린 값이다.
포함된 317개 중 HIS 가 41등가인 사례가 3건 있어 생물학적으로도 무리가 없다.
구조 자체는 정상일 가능성이 높으므로 **재조립보다 `f41_pos` 정정이 맞다.**

### 4.3 A0AC61KYD2 — 후보는 있으나 모티프 불일치

```
PHE43    3.91 A   이웃 PRO-PHE-GLN
```

거리는 정상 범위이고 Phe 이지만 Gly 측면이 없다. 정렬이 3잔기 밀린 것으로 보이나 확정 불가.
A0AC61SBG3 과 같은 `A0AC61*` 계통이고 CA 626개로 동일 — **두 구조가 한 계통의 공통 문제**일 수 있다.

### 4.4 A0A2N7PLW0 — 가장 애매함

```
ILE135   4.33 A   이웃 GLY-ILE-LEU   (반쪽 일치)
PHE130   5.25 A   이웃 GLU-PHE-GLU   (정렬이 지목한 것)
```

CA 가 **753개**로 전형값(~630)보다 120개쯤 길다. 여분 도메인이 전역 중첩을 끌어당겼을 가능성.
ILE 는 41등가로 18건 존재하므로 후보가 될 수 있으나 근거가 약하다.

## 5. 미해결 — 앵커 검증이 아직 안 됐다

Gly-x-Gly 를 판단 근거로 쓰고 있으나, **정상 대조 2건과 ChCODH2 하나로만 확인했다.**
317개 전체에서 이 모티프의 보존율을 재지 않았다.

```
보존율 90% 이상  -> 신뢰할 수 있는 앵커. 문제 구조의 중심 보정에 사용 가능
보존율 낮음      -> 앵커로 쓸 수 없음. dev 작은 구조는 그대로 두고 개별 판단
```

**더 중요한 것** — `center_dev` 는 작은데 정렬만 밀린 구조가 317개 안에 섞여 있을 수 있다.
현재 필터로는 안 걸린다. 앵커 검증이 그것도 함께 잡아준다.
검사 스크립트는 도킹 세션이 보유하고 있으며 `result/homolog_dock/anchor_check.tsv` 로 산출 예정.
